KEY FINDINGS
================================================================================

1. PAPER TRADING IMPLEMENTATION
   - Location: trading_bot.py, lines 179-206 (OrderManager.place_order)
   - Method: In-memory simulation using dictionary storage
   - Order ID format: PAPER-{unix_timestamp_ms}
   - Execution: Instant (no API calls, no waiting)
   - Controlled by: config.py line 77 (ENABLE_PAPER_TRADING = True)

2. LIVE TRADING IMPLEMENTATION
   - Location: trading_bot.py, lines 207-239 (OrderManager.place_order)
   - Method: Real Zerodha API calls with retry logic
   - Order ID format: Real exchange order ID
   - Execution: With 3 retries, 1-second delay between attempts
   - Status polling: Every 2 seconds for up to 30 seconds
   - Controlled by: config.py line 77 (ENABLE_PAPER_TRADING = False)

3. KEY DIFFERENCES
   
   Paper Mode:
   - Simulated orders created in memory (_paper_orders dict)
   - Instant completion (no API latency)
   - Uses current LTP from API for accuracy
   - No real money at risk
   - Best for testing and learning
   
   Live Mode:
   - Real orders sent to Zerodha exchange
   - Depends on market conditions and order type
   - With automatic retries (3 attempts)
   - Real capital at stake
   - Charges actually deducted from account

4. UNIFIED ASPECTS (IDENTICAL IN BOTH MODES)
   
   - Order confirmation logic (optional for paper, configurable for live)
   - Position tracking (Trade object + database)
   - Risk management (circuit breaker, position sizing)
   - Exit conditions (SL, target, trailing, time)
   - Charge calculation (real fees applied in both modes)
   - Database persistence (SQLite)
   - Command interface (emergency stop, status, etc.)

5. CONFIGURATION FILES
   
   Primary: /home/user/zerobot/config.py
   - Line 77: ENABLE_PAPER_TRADING (the master toggle)
   - Lines 14-26: Capital & risk management
   - Lines 76-88: Safety settings
   - Lines 64-75: Order settings
   
   Secondary controls via runtime prompts:
   - User selects Paper (default) or Live mode
   - Live mode requires explicit "CONFIRM" confirmation

6. ORDER EXECUTION FLOW

   Paper Trading:
   enter_trade() → place_order(paper=True) → Create PAPER-xxx → 
   Store in dict → wait_for_order() returns True immediately → 
   Trade object created → Database saved → Capital updated

   Live Trading:
   enter_trade() → place_order(paper=False) → Build API params → 
   Loop 3 times: call kite.place_order() → Get real order_id → 
   wait_for_order() polls status → Check for COMPLETE/REJECTED/CANCELLED → 
   Trade object created → Database saved → Capital updated with real price

7. POSITION TRACKING

   Both modes use identical system:
   - Active trades dictionary: self.active_trades
   - Trade object storage: Complete OHLC, entry/exit, P&L
   - Database persistence: SQLite trades table
   - Monitoring: monitor_active_trades() method
   - Exit triggers: SL hit, target hit, trailing SL, time exit

8. RISK MANAGEMENT

   All identical in both modes:
   - Position sizing: calculate_position_size() 
   - Stop loss validation: Min/max % limits
   - Circuit breaker: Daily loss threshold, consecutive loss limit
   - Emergency stop: Force exit all positions
   - Trading hours: Start/end times enforced
   - Daily limits: Max trades, max positions, max entries per stock

9. CHARGES & FEES

   Both modes calculate and apply:
   - Brokerage: ₹20 or 0.03% (whichever is lower)
   - STT: 0.025% on sell side
   - Transaction charges: 0.00325% on NSE
   - GST: 18% on brokerage + transaction
   - SEBI charges: ₹10 per crore
   - Stamp duty: 0.003% on buy side
   
   Paper mode: Simulated deduction
   Live mode: Real deduction from account

   - Entry conditions: identical
   - Exit conditions: identical
   - Risk management: identical
   - Position sizing: identical
   - Charge calculation: identical

2. Only Difference

     Paper: In-memory simulation
     Live: Real API calls to Zerodha

3. Testing Requirements Before Going Live
   - Run paper trading for 5-10 days minimum
   - Verify circuit breaker triggers correctly
   - Test emergency stop command
   - Check database records
   - Validate P&L calculations
   - Review charges breakdown
   - Verify trading hours logic
   - Test position sizing with various prices

4. Go-Live Checklist
   - Zerodha credentials correct in .env
   - API key and access token valid
   - Sufficient capital in account
   - Review ALL risk parameters in config.py
   - Start with SMALL capital first
   - Have emergency command ready (type: "emergency")
   - Monitor first few trades carefully
   - Keep terminal open during market hours
